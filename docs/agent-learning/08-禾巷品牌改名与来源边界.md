# 禾巷餐饮：品牌改名与项目来源边界

## 改了什么

项目对外演示名定为“禾巷餐饮 · 智能点餐与售后平台”。顾客售后网页、Java AI 点餐页、商家工单页、小程序导航与首页、Agent 系统自称、FastAPI/Swagger 标题及订单支付描述已统一；旧商家端是编译产物，不改课程资料原件，而在本地适配器响应时替换旧标题并提供新 SVG 标识。根 README 与面试导读已更新项目名称。

本次只改**展示名和品牌相关文案**。`sky-take-out` 仓库目录、`sky-*` Maven 模块和 Docker 服务、`com.sky` Java 包、`sky_take_out` MySQL 库、已存在的 OSS 域名及历史学习记录暂不迁移。它们被配置、脚本、镜像、持久化数据和已有链接共同引用；贸然全局替换会造成重建或数据迁移风险。旧 Logo 资源文件作为课程来源材料留在工作副本中，但当前首页不再引用它。

## 不能误导面试官的地方

“禾巷餐饮”只是我们给演示系统取的品牌名，不改变项目来源。基础外卖后端来自课程，商家管理端与小程序复用了课程资料中的编译产物；可以重点讲清自己扩展的 Agent、Java 内部工具接口、工单幂等、FAQ 对账、评测与前端适配。不要说整个外卖平台或旧前端从零独立开发。换名本身不增加工程含量，差异化主要来自可复现的功能与失败归因。

建议面试表述：

> 我把课程外卖后端作为业务基础，做了一个叫“禾巷餐饮”的本地演示系统。我主要负责扩展 Python 售后 Agent、Java 工具接口和工单处理链路，并对查单、FAQ 和幂等边界做了可重复评测。旧前端是课程编译产物，我通过本地适配接入，没有把它说成自己写的前端。
